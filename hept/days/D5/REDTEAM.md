# RED TEAM (D5-Q01..Q04)

Four red-team tests against the D4 machine. Each: what dies if the attack lands. No rhetoric defense.

## Q01 — DERIVATIVE TEST (is this just a known method restated?)
**Attack:** the five fields are pre-registration + receipts + append-only logs, i.e., lab-notebook discipline / empirical-software-engineering commonplaces. Every element (frozen criterion, raw output paste, cost commit, provenance chain) exists in versioned research logs.
**What dies if it lands:** the machine's claim to be a THEORY rather than a checklist; COULD_HAVE's five-field novelty downgrade collapses to zero novelty.
**Verdict: PARTIAL HIT.** The components are commonplaces (recorded as such). What is NOT derivative in the corpus: the UNVERIFIED-propagation (BK5 inheritance along citation edges) and the exposure-counted demotion (BK7) — both were generated BY the workspace's own failures, not imported. The theory's honest claim shrinks to: propagation + counted demotion + the refusal object. Everything else is engineering hygiene. THE MACHINE SURVIVES SHRUNKEN, not dead.

## Q02 — FORMALISM-IS-COSTUME TEST
**Attack:** the machine ships a 5-tuple state schema, relations, operations — but no executor exists; isn't this RCVM's costume in smaller clothes?
**What dies if it lands:** D4's output layer (RELATIONS_OPS, STATE_SCHEMA, GENERATOR formalism).
**Verdict: NO HIT, with a guard.** The difference: every formal object in D4 has a fails-when or teeth-test tied to a recorded failure (V-001, DS-P-001, BK7). The test's real demand — "delete the formalism and see if anything is lost" — was partially run in SUBSTITUTION (bland rename): the PROCEDURE survives, the formalism is ergonomic. Guard recorded: any D5/D6 addition must keep its teeth-test or be killed as costume.

## Q03 — ENGINE-DOES-NOT-GENERATE TEST
**Attack:** the engine's 9 runs produced mostly REFINING statuses and one subdivision (UNRUNNABLE); a real generator would produce moves nobody at the table anticipated. EX2 already confessed the stall is unexpressible.
**What dies if it lands:** the claim "another agent could generate a legal move" (D4 done-when) — if the engine only reproduces its authors' priors, it is a checker, not a generator.
**Verdict: PARTIAL HIT.** The engine generates INSIDE the refusal object but is blind to the stall (EX2, G8 invoices-not-fixes). The honest scope: the machine generates REFUSALS, not GOVERNANCE. Day 6's architecture must scope it exactly there or the claim is overreach. THE ENGINE SURVIVES AS A REFUSAL ENGINE ONLY.

## Q04 — WORKSPACE-INFIDELITY TEST
**Attack:** the theory is built from D1-D4 hept/ ledgers, but does it actually predict/explain the workspace it came from? Test against un-mined material: pr-006's receipt attacks, hypotheses-ledger's H6.
**What dies if it lands:** workspace-infidelity would make the canon a self-contained fiction.
**Verdict: NO HIT on prediction, ONE MISS recorded.** The machine predicted RUN07's fork non-firing and RUN11's UNRUNNABLE — both confirmed on real files. MISS: pr-006's receipt-attack math (forgeable receipts, sampling attacks) was never processed by the machine; a receipt is only as good as the sampler rule, and the machine's I1 byte-compare assumes honest command output — an attacker controlling the command controls the trace. THE P14 WALL HAS A KNOWN HOLE (command-level forgery). This goes to BREAKS (Q13) as B-case material.
