## What later wakes MAY do

1. BIND anchors: attach additional source locators (line numbers, quote ids) to CORE claims where the current anchor is a ledger reference — binding may only ADD precision, never change a claim.
2. REPAIR FAIL rows: if a future check falsifies a specific row (a BC row, an NC commitment flips, a number is wrong), that row may be marked FAIL with the evidence and patched — the patch must carry its verifier (file + method), per AGENTS.md.
3. Run the re-entry protocol (days/D6/Q04.md) — that is its designed use.
4. Re-verify HOLE.md against the source byte-for-byte (the D7-Q08 diff is the template).

## What later wakes may NOT do

1. Add modules, sections, or new quanta types to CORE — the 14-section order is final (kernel DAY 7 Q02).
2. Open site 2 — the kernel default stands even though the site is exhausted (kernel §6 post-exhaustion rule: densify CORE instead, and densification is limited to anchor-binding and FAIL-repair).
3. Re-theorize the rest of the workspace from this CORE (L19; CORE §11 already forbids the reverse direction — this forbids the forward one too).
4. Soften the negative contract (MUST_NOTs, CPs, bans, standing orders) without a flipped NC or an edited source — those are the only re-open paths (bore/SITE_EXHAUSTED.md).
5. Delete or rewrite ledgers; ledgers are the audit trail for every CORE row.
